# `data/` layout

Three tiers, kept separate so it's transparent where every number comes from:

```
data/
  raw/              ONE sub-directory per dataset, named by PAPER CODE.
    AM2018/  FM2012/  FMW2013/(+elena/)  FPM2006/  WF2013/  Bang2025/
    babyview/  seedlings/
    peekbank/       cross-dataset Peekbank infrastructure (1_d_sub.Rds = per-admin
                    LWL summary, _pb2026_admins.rds = admin->lab_subject_id bridge,
                    peekbank_stanford_* linkage)
    MANIFEST.csv    provenance: code, dataset_name, lab_code, language, channels,
                    citation, source, notes — one row per dataset.
  intermediates/    parse OUTPUTS consumed by the pipeline (not raw, not final):
                    *_cdi_items_long.csv (per-cohort long CDI), cdi_short_code_map_*.csv,
                    cdi_master_item_key.csv. Regenerated by the parse_*_cdi.R scripts.
  harmonized/       merged, clearly-formatted deliverables (for hand-checking + eventual
                    return to Wordbank/Peekbank):
                      cdi_item_level.csv      (gitignored: 47MB union; regenerable)
                      cdi_item_crosswalk.csv  (canonical item x dataset raw codes, hand-checkable)
                      input_level.csv         (per-recording input, all datasets)
                      lwl_session_level.csv   (per-session RT + accuracy, all datasets)
```

## Pipeline sketch
`raw/<code>/` --parse_*_cdi.R / prepare_*_lwl_rt.R--> `intermediates/` + per-dataset long CSVs
--> `build_harmonized_{cdi,io}.R` + `build_cdi_crosswalk.R` --> `harmonized/`.

Per-dataset provenance lives in each dataset's own README where present
(e.g. `raw/seedlings/README.md`) and in `raw/MANIFEST.csv`.

`data/chang_bergen_2022/` and `data/sperry/` are not part of the io-proc pipeline and
are left at the top level.
